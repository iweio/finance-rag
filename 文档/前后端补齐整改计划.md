### 3.2 逐条说明（只展开容易做错的）

**B1 两次 `done`** —— 契约 `API.md:108` 写明 `done` 出现 **1 次**，`MODULE.md:137` 又规定
`qa_id` 由 P1 填 `-1`、P3 落库后改写真值。现在 `generator.py` 自己发了一个 `done`，
`main.py` 转发完又发一个，前端收到第一个就收尾，**永远拿不到真 `qa_id`**，收藏按钮会挂。
改法：在转发循环里 `if event.event == "done": continue`，落库后自己发唯一一个。
**这条是"看起来能用、其实埋雷"的典型**——不报错，只是收藏功能悄悄坏掉。

**B2 `/meta/filters` 口径** —— 现实现从 `knowledge_point` 做 `GROUP BY`，就算把表灌满，
数也是**条文级**（合计 8156），而 `API.md:283-301` 的示例是**文档级**（合计 159）。
已实测 `语料元数据.xlsx` 的文档级统计与文档示例**逐项吻合**：

| 轴 | 实测（159 份） | `API.md` 示例 |
|---|---|---|
| `domain` | 银行 56 / 证券 56 / 综合 22 / 保险 14 / 外汇 11 | 一致 |
| `status` | 有效 155 / 尚未生效 3 / 已废止 1 | 一致 |
| `doc_type` | 规范性文件 63 / 部门规章 51 / 行政法规 16 / 法律 12 / 自律规则 8 / 司法解释 7 / 行业标准 2 | 一致（示例只列前二） |
| `org` | 23 个取值；人行 75、证监会 34、金融监管总局 23 | 人行 75 一致 |
| `topic_tags` | 22 个；合计 206（每份 1~3 个） | 债券市场 20、跨境与外汇 20 一致 |
| `date_range` | 19930301 ~ 20270301（150 份有值） | 一致 |

所以改法不是"给知识库灌数据"，而是**换数据源**：启动时读 `产出/语料元数据.xlsx`，按文档级聚合，
`org` 按顿号拆、`topic_tags` 按逗号拆，缓存 + 按 mtime 失效。四个注意点：
① `topic_tags` 各项之和 **206 > 159**，这是正常的（多选），前端别拿它当"总数"；
② 拆 `org` 时全角顿号 `、` 与半角都要认；
③ xlsx 缺失要报 `50003` 而不是返回空字典（空字典会让前端筛选器整块消失，且不报错）；
④ `count` 口径要写进 `API.md §5` 一句「文档数口径」，否则下一个改代码的人还会改回转条文数。

**B3 中文档详情** —— `retriever.OUTPUT_FIELDS` 少了 `doc_number`、`publish_date`、`expire_date`、
`fetched_at`、`chunk_type`，`service.get_clause` 于是硬编码 `None`/`0`。前端溯源卡片要展示
"文号 / 公布日 / 施行日 / 采集日"，这四项现在全是空。改法两行：`output_fields` 补 5 个名字、
`ClauseDetail` 映射补 5 行。**注意保留 `None`**（`expire_date` 159/159 全空），不要填 0。

**B4 时间格式** —— 契约原文：「`created_at` 是 `YYYYMMDDHHMMSS`，14 位。**注意与日期字段不同**，
这是时间戳不是日期」。现在 `int(dt.timestamp()*1000)` 出来是 13 位，前端按 14 位解析会得到 1970 年。

**B5 收藏补字段** —— 契约 §7 的 items 要 `doc_title`、`clause_no`。一次 `clause_id in [...]` 查
Milvus 就够了（≤50 条/页），不要 for 循环单查。

**B8 session 登记** —— 现在 `session` 表永远是空的，于是：`/history` 的 `40402 会话不存在` 永远不会触发、
标题列恒空、`qa_history.session_id` 是个没有外键约束的裸字符串。改法：`chat` 首次落库前
`INSERT ... ON DUPLICATE KEY UPDATE session_id=session_id`（幂等），`title` 取 `question[:30]`。

**B17 `MEDIUMTEXT`** —— 契约 DDL 写的是 `MEDIUMTEXT`，ORM 写成 `Text`（= MySQL `TEXT`，64KB）。
长答案超 64KB 会抛 1406，而且是在 SSE 已经吐完、用户已经看到答案之后才抛 —— 表现为"答案出来了，
但历史里没有、还偶尔 500"。**改一行，收益很实在。**

**B18 ORM 与 DDL 对齐** —— `models.py` 没声明 `uk_clause`、`uk_qa` 与 `idx_session_created`，
而 `create_all` 建表时不会自动加。于是一旦换真机用 ORM 建表，**DDL 文档和实际库不一致**，
`_contract_check` 也查不出来（它只比文档）。要么补 `UniqueConstraint`/`Index`，
要么废掉 `create_all` 改用 DDL 脚本初始化 —— **二选一，必须写进 README**。

**B20 认证（§9 #7 裁决要做，全篇唯一主动扩契约的一处）** —— 契约从 **8 个接口变 10 个**，
这已经不是"实现细节"，是**契约变更**，必须走 P1 签字 + 文档同步。落地要点：

| 项 | 取值 / 做法 | 理由 |
|---|---|---|
| 接口 | `POST /api/v1/auth/register`（`{username,password}` → `{user_id,username}`）、`POST /api/v1/auth/login`（→ `{token,user_id,username,expires_in}`） | 只加两个，不加 `me`/`refresh`；token 过期由前端解 `exp` 判断 |
| 密码 | `bcrypt` 哈希后存 `user.password`（VARCHAR(128) 够，bcrypt 输出 60 字节） | `DB.md` 已写明「bcrypt 哈希，不存明文」 |
| Token | JWT HS256，`sub=user_id`、`exp=+24h`，密钥读 `JWT_SECRET`；**生产环境缺该变量必须启动失败**，mock/开发模式才允许随机生成并打警告 | 密钥随机重启就全掉线；不 fail-fast 会把问题拖到演示当天 |
| 错误码 | 新增 `401 40101 未认证`（缺 token/无效/过期）、`409 40901 用户名已存在` | 现有 `40001/40401/50001…` 里没有认证类，硬塞会污染语义 |
| 归属 | `favorite.user_id` 填当前用户；`chat` 带 token 时把 `session.user_id` 写上 | `qa_history` 表**没有** `user_id` 列，历史归属只能借 `session.user_id` 关联，别去改 DDL |

`产出/chunks/{doc_id}.jsonl` 提供 `clause_id`/`clause_no`/`chapter`/`text`/`clause_index`，
`产出/语料元数据.xlsx` 提供 `doc_type`/`domain`/`org`/`doc_number`/三个日期/`status`/`source_url`/`fetched_at`。
脚本要求：`ON DUPLICATE KEY UPDATE` 幂等（可反复跑）、按 `doc_id` 合并、行数与 chunks 一致（8156）、

### 4.4 API 层

- `client.ts`：`axios.create({ baseURL: import.meta.env.VITE_API_BASE, timeout: 30000 })`；
  **请求拦截器**从 `auth` store 取 token 塞 `Authorization: Bearer`；
  响应拦截器统一拆 `{code,message,data}`，`code!==0` 抛 `ApiError(code,message)`；
  **`40101` 时清 token + 跳 `/login?redirect=<当前路由>`**；**`chat` 不走 axios**（要流式，见 §4.5）。
- `types.ts`：`ClauseBrief` / `SearchItem` / `ClauseDetail` / `RelatedClause` / `FilterDict` /
  `HistoryItem` / `FavoriteItem` / `Health` / `AuthToken` / `AuthUser`，字段名与 `契约/API.md` **逐字一致**。
- `auth.ts`：`login()` / `register()`；token 存 `localStorage`（key `rag_token`），
  **过期判断在前端解 JWT 的 `exp`**（只 base64 解码，不校验签名——校验在服务端）：
  过期即视为未登录，避免带着废 token 满屏 401。
- 每个接口一个函数，返回 `Promise<T>`，**不在这一层做任何字段重命名或默认值填充**。
- Mock 开关：`VITE_USE_MOCK=true` 时 `index.ts` 导出 mock 实现，否则导出真实现；
  **函数签名必须完全相同**，这样切回来不用改页面。Mock 下 `login` 接受任意 `demo/demo123`。

### 4.5 SSE 客户端（最容易做错的一块）

**`/chat` 是 POST，`EventSource` 用不了**（它只支持 GET、且不能带 body、不能设 header）。
必须用 `fetch` + `ReadableStream` 手动解析。要点：

```ts
// composables/useSSE.ts 的核心（示意，非最终代码）
const res = await fetch(`${base}/chat`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', Accept: 'text/event-stream' },
  body: JSON.stringify({ question, session_id, filters }),
  signal,                                   // AbortController，用于"停止生成"
})
if (!res.ok || !res.body) throw await toApiError(res)   // 503/500 走这里
const reader = res.body.getReader()
const dec = new TextDecoder('utf-8')
let buf = ''
for (;;) {
  const { done, value } = await reader.read()
  if (done) break
  buf += dec.decode(value, { stream: true })
  let i
  while ((i = buf.indexOf('\n\n')) >= 0) {   // 事件块以空行分隔
    const block = buf.slice(0, i); buf = buf.slice(i + 2)
    const ev = parseBlock(block)             // event: / 多行 data: / 忽略 ": comment"
    if (ev) yield ev
  }
}
```

必须处理的 8 件事：

1. **按 `\n\n` 切块**，不是按行；`data:` 可能多行，要 `join('\n')` 后再 `JSON.parse`。
2. **`event:` 缺省当 `message`**；`:` 开头是心跳注释，直接丢。
3. **认 5 类事件** `delta/sources/score/done/error`（`error` 已由 §9 #6 写进契约，见 B14）；
   仍未知的事件记 `console.warn` 后忽略——服务端以后再加事件，前端不该崩。
4. **`done` 去重**：B1 未修前后端可能收到两个，前端以第一个为准、第二个忽略——**防御性代码要留**，
   因为真机上不一定什么时候又冒出来。
5. **`error` 要能收尾**：收到后停止累积、把已出文本标成"未完成"、展示 `message` + 重试按钮；
   **不要**把 `error` 当网络异常处理，两者文案要区分。
6. **`AbortController`**：切路由/点"停止"/组件卸载时必须 abort，否则流没读完会占连接。
7. **异常兜底**：`reader.read()` 抛错（网络断）→ 把已累积文本保留、显示"连接中断，点击重试"。
8. **不要在 `delta` 回调里 `v-html` 全量重渲染**：按 30~60ms 合并一次（`requestAnimationFrame` 或节流），
   否则中文长答案会明显掉帧。

> 分句 delta 的粒度是**后端**决定的（§9 #4 裁决），前端只按事件流渲染，不要自己再攒一批再显示——
> 那样会把后端的流式努力又抹平。

### 4.6 Mock 层

  中间 `await sleep(80)`，然后 `sources` → `score` → `done`，**顺序与契约完全一致**。

### 4.7 筛选器

- 数据源只有一个：`GET /meta/filters`。**不许在前端写死枚举**（`契约/API.md §5` 明确要求）。
- 5 个轴：`domain`、`status`、`org`、`doc_type`、`topic_tags`；取值旁显示 `count`。
- `date_range` 用 `{min,max}` 做 `el-date-picker` 的边界，**值是 `int YYYYMMDD`**，
  提交时转回 int（`dayjs` 的 `value-format` 在这里反而容易出错，直接用 `format.ts` 里两个函数）。
- **`topic_tags` 只做字典展示 + 检索页本地标注，不进 `filters`**——已裁决（§9 #1）。
  `filters` 仍只有 domain/status/org 三个字段，前端别自作主张传第四个，后端会忽略。
- 空结果时显示"当前筛选条件下没有命中"，**并且给一个"清除筛选"按钮**——
  这是 `org` 归一前后最容易踩的坑（用旧简称筛，一条都没有）。

### 6.2 两个坑，提前写清楚

- **SQLite 跑测试**：`backend/models.py` 用了 MySQL 专有的 `DATETIME(fsp=3)` 与 `BigInteger` 主键。
  直接换 SQLite 会踩两件事：① `mysql.DATETIME` 在 SQLite 上要 `with_variant`；
  ② `BIGINT PRIMARY KEY` 在 SQLite 里**不是 rowid 别名**，`autoincrement` 不生效、插入报错。
  标准解法：`BigInteger().with_variant(Integer, "sqlite")` + `MySQLDateTime(fsp=3).with_variant(DateTime, "sqlite")`。
  **这是必须做的一处小改造**，否则测试只能连真 MySQL，而 CI/本机没有 MySQL。
- **SSE 测试**：`TestClient` 的 `stream()` 能读生成器，但要断言"逐块到达"得用 `httpx` 的
  `client.stream()`；`TestClient` 在同步生成器上会把内容一次读完。测**顺序和次数**够用，
  **别测"实时性"**——那是手工验收项。

### 6.3 覆盖率口径

`backend/` + `rag_core/`（mock 除外）。**不把 `rag_core/retriever.py` 的 Milvus 分支算进去**——
那部分要真库，本机跑不了。做法：在 `conftest` 里把 `retriever` 的 `_connect_milvus` 换成 fixture，
覆盖率报"可测部分覆盖率"，并在测试报告里写明口径。**别为了凑数写 `assert True`**，
`_contract_check.py` 那种交叉校验才是真正防回归的东西。

## 9. 九条裁决（2026-11-09 已定）

| # | 事项 | 裁决 | 理由（为什么不选另一个） | 落地到 |
|---|---|---|---|---|
| 1 | `topic_tags` 进不进 `filters` | **不加**，只做字典展示 | 加字段要同时改 API.md、`RagEngine.Filters`、Milvus 表达式（只能 `like`）与前端，四处返工且要重测检索；本轮价值不抵成本 | B2 只出字典；F11 只展示 |
| 2 | `/search` 的 `total` 语义 | **候选集数量（近似），上限 200**，写进 API.md | 精确 count 要额外查询且"命中"定义模糊（向量与 BM25 并集）；游标翻页则要废弃契约字段，验收更难解释 | B9、F6（`200+` 显示） |
| 3 | `related` 的「引用」类型 | **做**，排批次 5 | 差异化③明确要求四种关系，答辩必问"为什么只有三组"；0.8 天可承受，不做则枚举里留一个永远不出现的值 | B10、F7 分组、T2 |
| 4 | 流式程度 | **分句 delta**（一句一个事件） | 真 token 流式与"引用越界要剔除重生成"直接冲突——已吐出的字收不回来，得新增撤回事件再改契约；分句已能消除"卡几秒突然全出"的观感 | `rag_core/generator.py`、F3/F5 |
| 5 | `chat` 是否登记 `session` | **自动 upsert**，`title` 取首问前 30 字 | 不加接口、history 立刻可用；新增 `POST /session` 会超出契约，懒创建则拿不到首问内容 | B8 |
| 6 | SSE `error` 事件 | **写进 API.md**，作为第 5 类事件 | 改成 `done` 带 error 会污染成功语义；断流则前端分不清网络问题与 LLM 失败 | B14、F3、T3 |

| 9 | 数据层 SPEC v5 重跑 | **本轮不动**，答辩材料注明"产物为 v4 口径" | 前后端不依赖重跑；但要如实写口径，论文若称"表格已结构化"而产物没有属不实陈述 | 验收文档措辞 |
